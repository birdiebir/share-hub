# 開發日誌

## 2026-11-05

**做了什麼**
- 抽出共用層：`templates/partials/base.css`（色彩 token、App 殼、分頁列、卡片、安裝卡、離線條等）和 `core.js`（DOM 小工具、離線快取註冊、圖示、解密、照片署名等）。模板用 `/*__PART:檔名__*/` 標記，build 在算字型子集前展開；hub、trip 改用共用層。
- 新增 `article`（Markdown 文章，可分段）與 `resources`（連結清單，標籤篩選）兩個模板，以及 build.py 的 `validate_article`、`validate_resources`、內文警告、photos 型別檢查、照片 url 只收 https、封面備援。
- 首頁卡片依模板種類顯示圖示與小標（文章、清單）。
- `private.example/` 補 article、resources 範例與三張程式產生的示範插圖（內容全為虛構）。
- 測試：test_build.py 補共用層與新模板的單元測試；新增 test_templates_ui.py（Playwright＋Edge，沒裝就跳過），涵蓋 Markdown 元素、XSS、分段切換、標籤篩選、不橫向捲動。

**決策與理由**
- Markdown 用自寫的小子集、全程用 DOM 組而非 innerHTML；原始 HTML 一律當文字，連結只收 https 與 tel，圖片只認 `photos` 裡的名稱。build 只對來源網址、照片署名與型別擋下，內文的壞連結只警告，免得一個壞連結讓整頁發不出去。
- 共用層只抽「兩個模板長得一樣」的部分；h2 外觀、hero、動畫等各自不同的不抽，避免改動畫面。
- 通用版不含截圖比對工具與部署腳本（綁定特定部署）。

**踩坑與解法**
- 補丁套用到分叉過的檔案時，容錯比對會把一行放到錯的位置（卡片的小標 chip 跑出陣列），瀏覽器測試抓到語法錯誤；改成逐行對照來源修正。
- 文件裡的 Windows 路徑在某些寫入方式下，反斜線被當成跳脫字元吃掉；改用正斜線。
- 強調語法（粗體、斜體）的解析要避免回溯爆炸，有測試用 8000 個未配對的 `**` 驗證仍是線性時間。

**下一步**
- 在真實手機上目視確認 article、resources 兩頁的淺色與深色。
- 之後新增模板時，先沿用 base.css 的 token，不重寫。
